# Premises works — Cycle 22

`cd_world_premises` reports a scenario overlay, separate from immutable source
building identity, geometry and source capacity. Explicit technical wear reduces
condition (0–1000); zero blocks ordinary entry, housing and productive use.
Existing occupants may leave; qualified repair workers can use authorized repair
access through the same physical connectors. Care and food work also respect
premises availability. No unsupported historical decay rate is invented.

Repair and use changes each reserve one wood and one tool. Capacity works reserve
two wood, two clay and one tool. These quantities and a configured 1–10080 minute
labor requirement are technical assumptions. Materials must already be delivered
to the actual worksite. Qualified carpenter tasks supply shared native labor;
closure, rest and travel suspend progress. No output is published before labor
and prerequisites complete. Capacity must fit housing/visitors/physical occupancy,
workplace slots and clinic beds; otherwise publication waits without more wages.
Use changes require an explicit scenario label. Capacity is bounded 1–128.

Project keys are monotonically increasing per building, with identical-latest
retry returning the original result. Cancellation refunds held materials and
unfinished work reserves exactly once; paid labor remains earned. One pending
project per site and its latest result are retained. The source footprint and
historical use/identity are never rewritten. Runtime geometry changes are
unsupported: a new footprint requires a separately reviewed content generation.
